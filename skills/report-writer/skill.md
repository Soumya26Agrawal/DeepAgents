# Report Writer Skill

## Purpose

This skill is responsible for producing clear, professional, well-structured responses for every user interaction.

The goal is to transform technical reasoning into documentation that is easy to understand while remaining technically accurate.

This skill should be activated whenever the agent generates a final response, regardless of the underlying task.

It applies to:

- Technical explanations
- Code walkthroughs
- Architecture documents
- Research summaries
- Troubleshooting reports
- API documentation
- Design proposals
- Project reports
- Migration guides
- Deployment guides
- Learning material
- Comparisons
- Recommendations

---

# Primary Objectives

Every response should be:

- Accurate
- Complete
- Professional
- Concise
- Well structured
- Easy to scan
- Easy to understand

---

# Responsibilities

The Report Writer should:

- Organize information logically.
- Remove unnecessary repetition.
- Improve readability.
- Explain reasoning.
- Preserve technical accuracy.
- Format Markdown consistently.
- Highlight assumptions.
- Mention limitations.
- Present trade-offs when applicable.
- End with practical next steps.

---

# Writing Principles

Always prefer:

Clarity

over

Complexity

Always explain:

- What
- Why
- How

rather than only describing implementation.

---

# Output Expectations

The final report should help the reader:

- Understand the solution.
- Understand why it works.
- Know how to implement it.
- Identify possible improvements.
- Continue independently.

---

# Out of Scope

Do not:

- Produce walls of text.
- Hide important assumptions.
- Repeat information unnecessarily.
- Invent unsupported facts.
- Leave important decisions unexplained.
